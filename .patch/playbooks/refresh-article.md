# Playbook: refresh-article

> 90日以上更新されていない記事を1本選び、価格・スペック・在庫・リンク切れを再検証して更新する。

## 入力

- `src/content/**/*.md`（全記事）
- `.patch/queue/updates.yml`（手動指定があれば優先）
- `.patch/config.yml`

## 手順

### 1. 候補選定

優先順位：
1. `updates.yml` に `pending` エントリがあればそれを最優先
2. `pubDate` または `updatedDate` から `age_threshold_days`（既定 90 日）以上経過した記事のうち、最も古いもの
3. 候補がなければレポートに「更新対象なし」と記録して終了

### 2. 現状調査

- 製品の現在の販売状況を確認（販売終了・後継機登場・価格改定）
- アフィリエイトリンクが生きているか確認（404 / リダイレクト先変更）
- スペック・仕様変更の有無を確認

### 3. 更新内容の決定

| ケース | 対応 |
|--------|------|
| 価格が変わっている | 本文と frontmatter の `productPrice` を更新 |
| 後継機が出た | 「2026年版」セクションを追加し、後継機との比較を1段落入れる |
| 販売終了 | 冒頭に「**販売終了のお知らせ**」セクションを追加、後継機への誘導 |
| リンク切れ | 新しい URL に差し替え、または該当ストアを削除 |
| 仕様の重要な変更 | 該当セクションを書き換え、「2026年X月時点の情報」と明示 |

### 4. 更新実行

- 本文を編集
- frontmatter の `updatedDate` を今日の日付に更新
- 必要なら frontmatter に「`refreshNote: 価格改定（XX,XXX → YY,YYY 円）`」のような短いメモを追加（人間レビュー時の参考用）

### 5. 自己レビュー

- [ ] 価格情報が複数ソースで確認できている
- [ ] 「ここまでは確認済み、ここからは未検証」が更新部分にも書かれている
- [ ] アフィリエイトリンクが全部生きている

### 6. ビルド検証 + コミット

```bash
npm run build
git add .
git commit -m "chore(<collection>): <slug> を更新（<更新内容の要約>）"
git push origin main
```

### 7. キュー後処理

- `updates.yml` の該当エントリを `done` に
- `articles.yml` への影響なし

### 8. レポート追記

```markdown
## <時刻> 記事更新: <slug>

- 更新内容: <価格改定 / 後継機追加 / リンク切れ修正 / etc>
- 旧 pubDate: <YYYY-MM-DD>
- updatedDate: <today>
- build: pass / fail
- push: pass / fail
```

## エラー時

- 製品情報が取得できない → スキップして次の候補へ
- 全候補が取得不可 → レポートに記録して終了（人間に差し戻し）
